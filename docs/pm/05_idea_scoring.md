# 05 · Idea Scoring Matrix

> Each member scores 1–5 independently, then we average. Weights mirror the typical hackathon rubric; **re-weight to the official judging criteria** once they're published (see [01_hackathon_brief.md](01_hackathon_brief.md)).

## Weights

| Criterion | Weight | 1 = | 5 = |
|---|---|---|---|
| **PS fit & impact** | 25% | Tangential, small audience | Nails the PS wording, large/urgent pain, quantifiable |
| **Demo wow** | 20% | Static screens / a notebook | Live, interactive, memorable "moment" |
| **Feasibility in time** | 20% | Many unknowns, risky data | Core is buildable in about 10h with known tech |
| **Novelty** | 15% | Existing apps do exactly this | Fresh angle or a novel combination |
| **Technical depth** | 10% | CRUD / API passthrough | Non-trivial AI/data/systems work judges respect |
| **Team fit & data availability** | 10% | Needs skills/data we lack | Plays to our strengths; data is in hand |

**Kill criteria (any one → drop the idea):** required data is unobtainable in time · needs hardware we don't have · more than one unfamiliar technology on the critical path · no visual demo possible · violates event rules.

## Tie-breakers (in order)
1. Which one has the clearer **10-second demo moment**?
2. Which one can we get **end-to-end by T+7**?
3. Which one makes the better **story** (a real persona with a real pain)?
